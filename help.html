Projects and the folder #

A project is a folder on disk. The Projects page (index.html) lists the folders you have opened before; + New Project creates one, Open Project points at an existing folder. The browser asks for permission to read and write the folder the first time each session — that is the "requires permission" click on a project card.

Everything the scorer knows lives in that folder, in plain files you can read and back up:

FileWhat it holds
manuscripts/*.txtOne file per source — the transliteration with its § assignments. This is the text you edit in the Source Text pane. See Writing a source.
manuscripts/index.jsonThe order of the sources in the sidebar.
manuscripts.jsonPer-source metadata: type, provenance, period, the eBL siglum parts. Edited in Settings and in the "Describe this source" dialog.
score-data.jsonThe edition itself: every reading and variant, translations, notes and parallels on readings, the alignments from Positions, the lemmas, the project Dictionary, and the sent / revised marks.
score.txtThe synoptic score as plain text, rewritten on every save. Handy to read, not something to edit.
annotations.jsonThe Notes panel.
project.jsonName, eBL target chapter, siglum mapping.
images/Photographs and PDF pages per source, with their drawings.
export-*.atf, ebl-chapter-backup-*.jsonWritten by Export: a copy of the ATF that was sent, and eBL's copy of the chapter as it was before a destructive send.

The folder can sit in Google Drive, OneDrive or Dropbox and be shared. Read Saving, syncing, shared folders before two people work in it at once — the rules are simple but they matter.

Under the tab bar, while the Score tab is open, sits the score's own tools row — Lemmas, Dictionary, Positions, Check positions, Compose all. It goes away with the other tabs, so the tab bar keeps its width for the tabs.

The pill beside the project name says whether an eBL token is present. Without one everything works except sending; reading from eBL (fetching sources, pulling transliterations, the Parallels sweep) needs no token.

Sources #

Each row in the sidebar is one manuscript file. Click it to open it in the editor; the score does not change, since the score is always built from every source at once.

What a row shows

  • The name — museum number or eBL siglum. M# at the top of the list switches between the two for the whole app, score included.
  • Its period, and used/total: how many of its numbered lines carry a § assignment. A file reading 0/12 is a tablet not yet placed anywhere. Hover for the full count.
  • A colour band by type — library, commentary, excerpt, school… — with a legend at the foot of the list. The same colour marks its rows in the score.
  • Ctrl-click (or middle-click) the name to open the tablet in eBL's Fragmentarium in a new tab.
  • × removes the file from the project. It asks first.

Adding one

+ Add offers three ways:

  • Create New — asks for a filename (the museum number, e.g. K.3547) and starts the file with its name, @obverse and an empty §1 1..
  • Import Files — .txt files from your computer, already in the source format. Settings has a drag-and-drop version.
  • Fetch from eBL — type a museum number and the Fragmentarium transliteration is written as a new source. Nothing is assigned to a § yet: that is the editorial work, and the file is ready for it.

After any of these the Describe this source dialog asks for type, provenance, period and modifier — prefilled from eBL when it fetched the tablet. These four become the eBL siglum on export (Nin + NA + Ex + a number), so it is worth answering; Skip is there for when you do not yet know.

The Source Text pane

The editor colours the file's structure — surface markers, § markers, line numbers, $ directives, notes, parallels — and marks every bracket that has no partner on its line. The pane header counts them (3 unmatched brackets, hover for the line numbers). A bracket that only balances once a / alternative is expanded — m]i?-iq#-[tu₂/tu₄] — is accepted; only a line that balances under no reading is reported.

eBL entry ↗ opens the tablet in the Fragmentarium. Pull ↓ compares the file with eBL's transliteration line by line and shows what differs; you tick the lines to take. A pull rewrites only the transliteration after the §N n. prefix — every § assignment stays as it was, because those are yours, not eBL's.

Joins ⇄ opens the Joins tab with this tablet chosen and asks eBL's join finder about it.

Writing a source #

A source file is the tablet's transliteration, one line per tablet line, with a § in front of each line saying which chapter line it attests. That prefix is the whole mechanism: the score is nothing but every source's lines grouped by their §.

K.2246
@obverse
§1 1. DIŠ ina {iti}BARA₂ {mul}UDU.IDIM IGI-ir ina KUR DU₃.A-[B]I ŠE u ŠE.GIŠ.I₃ SI.SA₂
§2 2. DIŠ {mul}UDU.IDIM ina {iti}BARA₂ it-tan-mar GU₇-ti {d}U.GUR a-bu-bu
§3 3. DIŠ {mul}UDU.IDIM ina {iti}KIN it-tan-mar GU₇-ti {d}U.GUR a-bu-bu
$ single ruling
§32 19. DIŠ {mul}UDU.IDIM ša₂ {d}nin.urta MU-NI ina GU₄.UD-iṭ {d}UTU-ši KI {d}30 it-tan-mar#
#note: alternatively KI 20 ŠU₂ IGI
§32 20. ($___$) KIMIN KI 30 SIG IGI ina {iti}KIN U₄.7.KAM@v lu U₄.14.KAM@v
50. DIŠ {mul}UDU.IDIM SA₅ ana A₂-šu₂ {mul}G[E₆ ...] GE₆
@reverse
§74 1'. [...] x [...]
§83b 8. [DIŠ ṣal-lu-mu]-u₂ ša₂ {mul}UDU.IDIM IGI DU₃.A.BI MU BI KUR₂ ZI-ma
// F K.3547 r 13'
@colophon
45'. [DUB.5]6.KAM@v DIŠ U₄ AN {d}+en.lil₂ x [...]
LineMeaning
first lineThe source's name. Kept as the file's title; not a tablet line.
@obverseSurface marker: @obverse, @reverse, @edge, @left edge, @right edge, @top, @bottom, @colophon. The score shows the surface abbreviated beside the line number (K.2246 r 28').
§32 19. textTablet line 19, attesting chapter line §32. Primed numbers are fine: §74 1'.. Any label before the dot is accepted — §5 iv 3. — though plain numbers sort best.
§83b 8. textThe letter puts this line under the chapter line's second reading rather than its main one: b is the second, c the third. See Variants. You rarely type this by hand — the variant dialog and dragging write it for you.
($___$) textA continuation: the tablet line runs on into this one. It is shown under its witness in the score, indented, and counts as part of the same reading in Positions.
50. textA line with no §: transcribed, but not yet placed. It appears nowhere in the score and counts in the sidebar's used/total.
$ single rulingA ruling on the tablet (single, double, triple). Shown under the witness whose lines it follows. Any other $ line — $ rest of tablet blank, $ broken — is a tablet remark, shown the same way.
§18 $ single rulingA ruling assigned to a chapter line directly, for when it should sit under a particular § rather than follow the previous witness line. §18 18. $ single ruling is the same with the tablet line named.
#note: textA note on the witness line above it. Shown under that witness in the score and sent to eBL as that manuscript line's note. More than one is allowed. Notes on the reading are written in the score, not here — see Notes and parallels.
// F K.3547 r 13'A parallel for the witness line above it, in eBL's form: F a fragment by museum number, C a composition, then the line. Collapsed under the witness in the score.
@colophonEverything after it is the colophon. It is left out of the score and collected in the Colophons tab; the Parallels sweep uses it to find tablets from the same scribe.

A note or parallel attaches to the line directly above it. If that line has no § — an unplaced line — they attach to it and stay out of the score with it.

Reading the score #

The score is one block per chapter line, in § order. The score is always rebuilt from the source files: nothing in it is stored separately except what you write into it — the reading, the translation, notes, parallels, and everything Positions and Lemmas record.

One block

  1. Translation — the line above the reading. Editable in place; it becomes #tr.en: on export.
  2. § number and reading — the composite text. Editable in place: click into it and type. While you are not editing, brackets and determinatives are set in colour so the line reads like the edition; while you edit, it is plain text so the caret behaves.
  3. Marks — · or ✓ for sent to eBL, · or ✎ for revised, and ✖ / ⚠ when a send left something to repair. Explained in Marks and Reports.
  4. A numbered dot when the Notes panel has open notes anchored to this §; click it to see them.
  5. Actions — # Positions, L Lemmas, ⇗ validate and send this one § to eBL, and +.
  6. Witnesses — one row per source line, coloured by the source's type. The siglum is a link: it opens that source in the editor, at that very line. Continuations, witness notes, rulings and parallels follow their witness.

The + menu

NoteA #note: row under this reading. One per reading, so the entry greys out once there is one. Ctrl+Shift+N while the caret is in the reading does the same.
ParallelA // row. As many as needed. Ctrl+Shift+P in the reading.
Compose from witnessesWrites the reading from the witnesses' majority, sign by sign. See Composing.
Compose from…The same, from a chosen group of witnesses only.
Report on this readingWhat the reading you have chosen costs in attestation, without changing it.
Check positions of this omenThe positions check for this § alone — every reading and every witness of it.
VariantA second reading of this line. See Variants.
Delete this variantOn a variant row only. Its witnesses go back to the main reading.

To delete a note or parallel row, clear it and click away. The prefix chip is not text — you cannot type over it or lose it.

Order within a block

Witnesses sort by type, then by source. A ruling sits under the last line of the witness it follows. Where a witness was moved to a variant before its ruling was, the ruling is shown where the lines are, not where the file happens to say.

Variants #

A variant is a whole second reading of a chapter line, with its own witnesses — not a word in an apparatus. This is eBL's model too: a line has readings, each reading has manuscripts. §12 with two readings looks like this in the score:

§ 12   DIŠ {mul}UDU.IDIM ina {iti}GAN iṣ-ru-uh-ma MU₂.MU₂ DINGIR-MEŠ UB.DA.LIMMU₂.BA LU₃-MEŠ
       K.2173 o 12   DIŠ {mul}UDU.IDIM ina {iti}GAN iṣ-ru-uh-ma ...
§ 12b  DIŠ {mul}UDU.IDIM ina SAG {iti}GAN iṣ-ru-ur-ma MU₂.MU₂ DINGIR-MEŠ ... KIMIN ina {iti}KIN
       K.2246 o 12   [DIŠ {mul}]UDU.IDIM ina SAG {iti}GAN iṣ-ru-ur-ma ...

Making one

+ → Variant. Select part of the reading first and the dialog opens with that text prefilled. Tick the witnesses that attest the new reading; their §12 becomes §12b in their files. The main reading keeps the plain number.

Moving a witness between readings

Once a line has two readings, each witness row grows a handle at its right. Drag the handle — or hold Ctrl and drag anywhere on the row — onto the reading it belongs under. The § letter is rewritten in the file; a witness spread over several lines moves with all of them, and its rulings follow.

The letter is this app's own device. eBL numbers the chapter line once and keeps the readings in order under it, so §12b never appears on eBL — but the second reading and its manuscripts do.

Notes and parallels on a reading #

Both are added from the + menu and edited in place. They go to eBL with the reading. The ? beside a note row brings you here.

A note is markup, not free text

eBL parses a #note: line as a sequence of tagged and untagged runs. Outside a tag the text may not contain @, { or } — one stray brace and eBL refuses the whole line, not just the word it sits in. That is why any transliteration in a note, and any determinative in particular, has to be wrapped.

TagFor
@akk{…}Akkadian transliteration. Required for anything with braces: @akk{{mul}UDU.IDIM}. The content is parsed as ATF and shown in the transliteration font, so it has to be well formed.
@sux{…}Sumerian.
@es{…}Emesal.
@i{…}Italics, for a word of prose.
@bib{KEY@pages}A bibliography entry by its eBL id; the pages are optional.
@url{https://…}{label}A link; the label is optional.

Tag each citation on its own. One @akk{} around a whole sentence would ask eBL to parse the English as ATF.

#note: § 83 and § 86 differ only in the body named. UrkHel1 r 8 names @akk{{mul}UDU.IDIM} and could stand with § 83, but its wording is this omen's — @akk{i-da-aš}, and @akk{KUR₂ BI} before @akk{DUGUD-šu₂} — against § 83's @akk{KUR DU₃.A-BI TUR-ar₂} and @akk{ina DUGUD-šu₂}; it is edited here.

A parallel is a reference, not prose

A // row names another text in eBL's grammar: F for a fragment, C for a composition, then where.

// F K.3547 r 13'
// F BM.35903 4'
// C D 1 4 SB 55 12

A cf. before the letter marks a looser parallel: // cf. F K.7180 3'.

Pointing at a tablet

Name a source and a line in a note — UrkHel1 o 59, K.2246 r 28', AO.6450 8 — and a chip appears beside the note that opens that source at that line, surface and all. A name counts only if the project has it: the museum number the file is named by, or the eBL siglum the project maps it to. The surface is optional but worth giving, since a tablet numbers each side from its own 1.

On eBL the note stays as written. Note markup has no tag for a fragment; the only link it allows is @url{https://www.ebl.lmu.de/library/AO.6450}{UrkHel1 o 59}, which you can write by hand if a clickable reference matters there. A // parallel row is what eBL renders as a link to a fragment — use that when the reference is a parallel rather than a remark about one.

Notes on a witness

A note that is about one tablet's reading rather than the chapter line is typed in the source file, as a #note: line under that witness line (Writing a source). The same markup rules apply, and references in it get chips the same way.

Positions #

Positions mode is where you say which word of a witness answers to which word of the reading. This alignment is what eBL's hover follows, what marks omissions with ‡, what lets a witness word inherit a lemma, and what the tallies and statistics measure. It is worth doing for every line you send.

Turn it on for one line with # in its header, or Alt+P with the line under the cursor; for the whole project with Positions in the tools row above the score, or Alt+Shift+P.

What you see

The reading becomes a ruler: each word numbered from 0 and coloured. Dividers (:) and placeholders ([...], x) are numbered too, because eBL numbers them, but shown grey — nothing aligns to them. Under it, every witness word carries a small box.

Filling it in

  • Type the number of the reading word each witness word answers to. The word takes that position's colour as you type, so a misnumbering is visible at once.
  • Enter commits and steps to the next box; Shift+Enter steps back. Tab works as well.
  • Leave a box empty for a word that answers to nothing — a plus, a gloss, something the witness adds.
  • Two witness words may point at one position (a word written twice; a commentary quoting its lemma and then quoting it again). The tally names it.

The quickest start is + → Compose from witnesses, which writes the reading and its alignment in one go, so Positions opens already filled in and you only correct. See Composing.

The tally

Under the last line of each witness, the verdict for the whole omen:

✓Every position accounted for; nothing differs.
omits 5,6,8Positions the witness preserves the stretch around, but has no word for. A claim about the tablet.
lost 20–24Positions inside a break. Not a claim — a broken tablet says nothing.
reads otherwise at 1,3,14A word is there, but its signs differ from the reading's. Compared as signs, so {iti}BAR₂ against {iti}BARA₂ is one word and IGI against IGI-ir is a complement, not a difference.
two words at 7Two witness words point at position 7.
1 unplacedA witness word with an empty box.
⋯On the earlier lines of a witness that spreads the omen over several — the verdict is under its last line.

The daggers

A ‡ before a reading word is what eBL will print there: some witness either reads that word differently or has not got it. It is shown in the score so the published line can be seen before it is published. Hover for which witnesses.

Click any reading word to see, omen by omen, who has a word there, who omits it, who is broken, and who reads otherwise.

Alignments are stored per witness line, so two lines of one tablet under one § never share one. When a tablet gives an omen over several lines, the tally reads them as one stream.

When the reading changes

A box holds a position number, and so does a lemma. Insert a word into the reading and every number after it would point at a different word — which is what happened to §88 and §89 while they were being rebuilt. So the numbers now follow the words: when a reading is edited, its old and new tokens are paired up and every box and lemma is carried across. A respelt word keeps its boxes and its lemma (the lemma drops back to suggested, since someone should look at it again); a word that disappears takes its boxes with it, leaving those witness words unplaced. The same carrying happens when a witness is moved to another reading, whose words are numbered differently.

For anything aligned before this existed, and for anything that slips past it, Check positions in the tools row above the score asks three questions of every aligned row in the project — or, from a reading's + menu, Check positions of this omen asks them of one § alone, which is the way to work a long omen while its reading is still moving:

  • Does each witness word resemble the reading word its box points at? Tolerantly: a plural marker (-MEŠ, -ME, HI.A), a phonetic complement (IGI against IGI-ir), a determinative and damage marks do not count, a spelling that shares nine tenths of its signs passes, and so does a witness word the dictionary would give the same lemma the reading word carries — ti-bu against ZI-ut, both tību — once the reading word has been lemmatized. Below that the pairing is raised — 73 % alike — and a pairing with nothing in common is raised louder, since that is what a box left over from an older reading looks like.
  • Do the words fit better a few positions over? Asked strictly, because EAE repeats its phrases and a coincidence four words away is common: only a run of boxes that all agree on the same shift, and fit clearly better than in place, is reported, with an Apply that slides the boxes from the first drifting word onward. A box that would leave the reading is emptied rather than pointed at nothing.
  • Does any box point past the end of the reading, or belong to a word the line no longer has? Each can be emptied with one press.
  • Is a position taken twice? Asked of the whole omen, across every line the witness gives it, since a tablet that needs three lines for one omen numbers them as one stream. The first word keeps the position; each later one is raised — a commentary quoting its lemma twice is the honest case, and gets OK.
  • Does the numbering run backwards? Read in tablet order, line after line, the positions should climb; 28, 29, 12 is raised at the 12, and so is a second line that starts below where the first ended.

Nothing changes until you press something. A pairing that is right as it stands — a genuine variant, a syllabic spelling of a logogram — gets OK, which declares those two writings one word for the whole project: IGI-ir against it-tan-mar, accepted once, is never raised again in any omen, either way round, and every other pairing of the two in the open report is settled with it. Only here accepts one box without saying anything about the words elsewhere — for the scribal slip you have decided to live with. A whole row can be accepted at once. The acceptances are saved with the project (acceptedPairs and alignmentOk in score-data.json), so they survive closing the app and a collaborator's check honours them too.

Lemmas and the Dictionary #

Lemmas mode gives each word of the reading its dictionary word — amāru I, bibbu I. Witness words are not lemmatized separately: each takes the lemma of the reading word it is aligned to, which is why aligning a line first makes the lemmas come with it.

Turn it on for one line with L or Alt+L; for the project with Lemmas or Alt+Shift+L.

What you see

Each word of the reading becomes a chip with its lemma written under it, in one of four states:

no lemmaNothing chosen yet.
suggestedThe dictionary's proposal, not yet confirmed. Shown lighter.
confirmedChosen or accepted by an editor.
blankNothing to lemmatize — a divider, a number, a placeholder. Skipped by Tab.

With the mode off, a line that has lemmas shows them in a thin strip under the reading, so they stay readable without the chips.

The picker

Click a chip, or Tab to it and press Enter. A list opens under the word — the dictionary's candidates for that spelling, each with a guide word and, when it applies, why it was suggested.

typeFilters the list. Type a lemma id the list does not offer and it is taken as written.
↑ ↓Move in the list.
EnterChoose the highlighted lemma and confirm the word.
Ctrl+EnterChoose it and record it in the Dictionary for the project — from now on this spelling suggests this lemma first, everywhere.
the pinSame as Ctrl+Enter, by mouse.
Tab / Shift+TabAccept what is in the box and open the next (previous) word. This is the whole of the work: read the suggestion, accept it or change it, move on. Accepting counts as confirming.
+Adds a slot: a compound logogram is one writing for two words, and after the + the candidates are offered again for the second — ṣītu I + šamšu I in two picks.
EscClose without changing anything.

Filling a chapter

Shift-click the L of a line to prefill suggestions from that line to the end of the chapter. Prefill only fills what is empty, so it is safe to run again; it never overwrites a choice.

The Dictionary

Dictionary in the tools row above the score, or Alt+Shift+D. The general dictionary knows what IGI can mean; it cannot know that in this edition it is always amāru. Recorded here — as Written → Read as — the decision is made once instead of on every line, and it outranks everything the shipped dictionary would offer. Spelling is normalised, so IGI, igi and {d}IGI are one entry.

The Dictionary lives in score-data.json beside the lemmas. Export for another project and Import a dictionary carry it between editions: the readings you settle for one text are usually the ones you will settle for the next.

Composing a reading #

Composing writes a reading from its witnesses, taking at each position what the majority reads, sign by sign, and writes the alignment behind it at the same time. It never runs on its own: it replaces text an editor may have weighed for a long time, so it runs only when asked, and asks again if the reading is not empty.

Compose from witnessesAll witnesses of this reading vote.
Compose from…A picker of scopes: every witness, one provenance, one period, one type, or a single tablet — each with the number of witnesses it would take. Options that would select nothing are not offered. For "give me the Nineveh text" or "what does the Uruk copy alone say".
Compose allEvery reading in the project. Overwrites what is there; asks first.
Report on this readingFor when you have chosen a reading the witnesses do not most attest — a lectio difficilior, a form the majority corrupted, a house spelling. That is a decision, not a mistake, and the report shows exactly what it costs in attestation without offering to overwrite it. It writes nothing.

Every composition ends in a report: what was taken from whom, where the witnesses split, and which words were set aside as illegible. Read it before trusting the line.

The other tabs #

Colophons

Everything after @colophon in each source, gathered in one place, with the source named. Nothing to edit here; edit the file.

Parallels

A sweep of the whole Fragmentarium against this project's sources, to find fragments that transmit the same composition or come from the same scribe. The corpus is eBL's sign dump, cached locally on first use, so a sweep costs no requests and can be re-run freely.

  • Sign run — how many signs in a row must match. 3 is the default and the safe one: what is being hunted is broken fragments preserving short stretches, and longer runs lose them. Raise it when a list comes back too noisy.
  • Weighting — Rare sequences scores a match by how unusual its sign runs are; Plain overlap just counts them. Rare sequences finds the known pieces better and is the default.
  • Source — pool every source into one query (the default, because the union of the witnesses is what finds missing ones), ask with a single tablet, or ask with the composite text alone.
  • Range — restrict to chapter lines (35-60, §40) or one tablet line of the chosen source (o 59, r 12').
  • Ignore fragments under — drops tiny fragments that match by chance.

Each hit scores on two channels: Text — shared composition, so another witness — and Colophon — shared scribe or library, so a join candidate. Click a hit to read the whole fragment in a tab of its own beside Images, without it becoming a source; Add as source when you are sure. Mark as checked records that someone has been through it, with the date, so the list can be worked down across sessions.

Joins

eBL's join finder, for one tablet at a time, with the lists kept in view. Choose the tablet in the bar (the open source is chosen for you) and Ask eBL. eBL reduces each side of every fragment to the sequence of its line types — text line, single, double or triple ruling, the start and end of a side — and ranks the whole Fragmentarium by how far another fragment's sequence continues this one's, which is the shape a physical join has. eBL answers with two rankings of fifteen — Score, the longest overlapping run, and Weighted, where a ruling or an edge counts for far more than a text line, the one that finds a join across a ruling — and the tab shows them as one table, a fragment per row with both its scores — so a fragment on both lists is one row, and the count above the table says how the thirty became fewer: 22 candidates — 15 by score, 15 by weight, 8 on both lists. Once the ranking is in, each candidate's Fragmentarium record is fetched as well, and the table fills in what the ranking cannot tell: the genre eBL files it under (Šumma ālu is not worth a look, however well its rulings fit), how many lines it has, its site beside the period, and its physical description on hover over the number. Click a column head to sort by any of these (click again to reverse); the filter box narrows by number, period, genre, site or description, and a word with a minus in front excludes — -ālu drops every Šumma ālu fragment; the Genre list does the opposite, keeping one; tick hide what is in the project or already joined to see only what is new.

It reads only the transliteration's structure — not the physical description, the columns, or where lines end — so it is a strong signal for a text ruled after every omen and blind to everything else. A candidate already among the sources is marked in project; one eBL already records as joined to this tablet, joined at eBL. Any other can be opened in a tab beside Images or added as a source, as from Parallels. It needs an eBL login with the transliterate:fragments scope — an editor's token, pasted in Settings; otherwise the tab says so.

Paradigms

Template twins of one chapter line across the corpus: lines that agree with it for three signs on either side of a short middle that differs. The distinct middles, decoded and ranked by how many contexts attest them, are the paradigm of that slot — planets in a planet slot, verbs in a verb slot. For "what else was written here in this formula".

Statistics

Every section measured against its own witnesses at once — how many attest it, how far they agree — so the edition can be read as a whole rather than one omen at a time. The sections where the witnesses disagree are where the editorial work is, and this is the only place that is visible without opening each one. It writes nothing.

Images

Photographs, hand copies and PDF pages, per source. Open a source, then + Upload: PNG and JPG are stored as they are; for a PDF a page picker opens and the chosen page is saved as an image. Thumbnails open the viewer.

The Notes panel #

Working notes for the project — things to check, questions, references, bugs in the app — kept in annotations.json, never exported. Not to be confused with the #note: rows in the score, which are part of the edition and go to eBL.

A note has a type (commentary, reference, bug, enhancement), a title, an optional description, and optionally an anchor: a source, a §, or both. Anchored notes show chips that jump to the source or the score line, and the § line in the score wears a numbered dot while any note on it is open.

A note anchored to a § remembers what the line read when it was written. If the text changes afterwards, the note shows text changed with the old reading on hover — notes are references, not tethers, so on a mismatch the panel flags it rather than guessing where the line went.

The filter narrows by state or type; clicking a dot in the score narrows to that §. Resolve a note when it is done; it stays reachable under Resolved. The badge on the button counts open notes and turns red while any of them is a bug.

Each § header carries two marks that answer, reading down the page, "what still needs sending?" and "what still needs reading?" — without anything having to be opened.

Export to eBL

The dialog first shows what it is about to act on: the target chapter, whether a token is present, the manuscripts and their state, and On eBL now — how many lines the chapter currently holds, with list them to see them in eBL's order. Reading only; nothing is sent by opening the dialog.

What to doEffect
Validate onlyChecks the ATF with eBL's own parser. Nothing is sent. Run this first, always.
Replace all linesBacks up the chapter, deletes every existing line, then imports these. Lemmatization and alignment eBL held on the old lines are lost — for a chapter's first upload, or a deliberate reset.
Update one lineReplaces a single § in place. Every other line keeps its lemmatization and alignment. The everyday send.
Update a range of linesThe same for §a to §b in one request.
Send the alignmentThe Positions data for the whole chapter — which witness word answers to which, and what it reads if it differs. This is what eBL's hover follows, and a line export cannot carry it, which is why it is a step of its own.
Send the lemmasThe Lemmas data for the whole chapter. Witness words take the lemma of what they are aligned to, so align first.
Remove lines from the endDeletes a run of lines from a chosen position down to the last. Only ever a tail, never a gap in the middle, so nothing left behind can shift. Use it to cut off strays appended out of order, then send those sections again.

Options under the modes:

  • …and the alignment after, …and the lemmas after — for a line send. eBL rebuilds a line's tokens from the ATF it is sent, so the alignment and lemmas it held for that line are gone the moment the line lands; sending them again is what keeps the line whole. On by default.
  • Register manuscripts first — a witness eBL does not know is left out of every line that quotes it, so a new tablet has to be registered before its lines can go. Off by default; tick it the first time a tablet goes. Settings does the same with more control.
  • Save a copy of the ATF in the project folder — export-<time>.atf, a full snapshot of what was sent. Cheap insurance.

What will be sent shows the exact ATF. Below it the steps light up as they run, and the result says what happened — and writes a report. A destructive mode backs the chapter up first as ebl-chapter-backup-<time>.json, eBL's own copy of it, so a bad send can be undone from the folder.

The ⇗ on a § header is Update one line for that § alone, with the same validation and the same report.

A send replaces the whole line object on eBL. Anything on that line that this project does not carry — an ‡ omission an editor marked by hand on the site, an intertext — is read from eBL first and sent back as it stands, but only if the send goes through here. Editing the same chapter on the site and from the scorer at the same time is the one thing that cannot be made safe.

Saving, syncing, shared folders #

Saving

Edits land in memory at once — the score follows a keystroke a moment later — but reach the disk only on Save or Ctrl+S. The status turns amber the moment something is unsaved, and the browser warns before the window is closed with unsaved changes.

There is deliberately no autosave. On a cloud-synced folder a file rewritten every few seconds is a file the sync client keeps duplicating as "conflicted copies"; one write per intentional save is what keeps the folder clean. Position boxes and lemma picks, which used to write on every entry, now save a moment after you stop; Save flushes anything pending first.

How a file is written, and why it matters on Drive

A browser cannot modify a file on disk; it can only write a new one and swap it over the old. A sync client sees that swap as delete, then create. On a shared Google Drive folder, when the file belongs to another account, the create is sometimes refused — Drive then moves your save to its lost_and_found folder and pulls its own copy back, and the scorer's folder poll reloads that copy. The save looks done and is gone.

When the scorer runs as the desktop app (or from its own server), saves go through the server instead, which writes into the existing file — a plain modification, which any sync client accepts and which keeps the file's identity and version history. The page cannot learn where a picked folder lives, so the first time a project is opened this way it asks for the folder's path, once per computer; after that the choice is remembered. Decline, and the browser's swap is used as before. Nothing else changes: the same files, the same folder.

Syncing

The folder is polled for changes made outside this window — by a collaborator, by the sync client, by you in another tab. A changed source is reloaded and the score rebuilt (the status says Synced); the source you are typing in is left alone while the editor has focus. A rebuild that arrives while a lemma picker or a position box is open waits until you are done with it, so nothing half-typed is lost.

Two things the poll will not do. It will not mistake your own save for a change: a sync client rewrites a file's time a few seconds after the save, once the cloud has it, and the app recognises the file it wrote itself by its stamp. And it will never reload a file over edits you have not saved — score-data.json or a source: if the file really has changed underneath you — another window, another person — the status turns red and says so, your edits stay, and you choose: Save to overwrite the file with yours, or reload the page to take theirs. A source you edited and then left for another is held in memory until you save; Save writes all of them.

Two windows of the same project on one machine talk to each other directly: a save in one reaches the other at once.

Working in a shared folder

One person per file at a time. A save writes whole files — a source file, or all of score-data.json. Two people saving the same file are not merged; the second save replaces the first. Agree who has the score open, and who has which tablets.

  • Before starting, save and wait for the sync client to finish; after finishing, save and wait again. The folder poll then hands your work to the other side cleanly.
  • Google Drive keeps a version history per file (right-click on drive.google.com → File information → Manage versions). It works as long as the file keeps its identity; a client that deletes and recreates a file on save starts that file's history over, and the old one goes to the trash for 30 days. If a folder shows two files of one name, that has happened.
  • The export ATF snapshots and chapter backups in the folder are the other safety net: every send leaves behind a complete copy of the score as it was.
